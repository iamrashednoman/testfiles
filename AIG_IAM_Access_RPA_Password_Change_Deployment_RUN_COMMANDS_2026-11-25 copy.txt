=====================================================================
 AIG IAM Access RPA - DEPLOYMENT RUN COMMANDS
 Fujitsu Mainframe service-account password change (latest release)
=====================================================================
 Who     : the server administrator, signed in to the server as the
           BOT ACCOUNT (the account that runs the scheduled task).
 Where   : each production server. The console in a browser, File
           Explorer, Task Scheduler, and Windows PowerShell 5.1 opened
           with "Run as administrator".
 Time    : about 30 minutes per server, plus 15 minutes of checks.

 HOW TO READ THIS FILE
   Most steps can be done in two ways:
     GUI         the console, File Explorer or Task Scheduler. Use this
                 way first.
     POWERSHELL  the same step as commands, for a scripted or remote
                 run, or when the GUI way is not available.
   Do ONE of the two for each step, not both. A few checks exist only
   as PowerShell (marked "PowerShell only").
   [OK] is the expected result, [NG] a result that needs action.

 THE UPDATE PACKAGE
   The update package is the newest zip supplied for this release. Its
   name can be anything. In this file it is called <package>.zip.
   
   This file is for a release that contains the Fujitsu Mainframe
   service-account password change: password age tracking, the
   automatic change on Task 0890 (90-day expiry, change from day 80,
   reminder and urgent e-mails, lock-out protection), and "Change
   service-account password" on the console. After the update,
   "change automatically" is OFF: the bot only tracks the password age
   until it is switched on.

 STEPS
   0   Before you start (both servers)
   1   Take a backup of the current folders (zipped)
   2   Download the package and keep it on the server
   3   Extract the files and run the precheck
   4   Stop the bot service, then zip the data folder
   5   Replace the files in the application folder
   6   Start the bot service with the scheduled task
   7   Sign in and validate the changes
   8   Going back (only if needed)
   9   Critical information

=====================================================================
 Both servers use the same database, so they must run the same files.
 Order of work:
   a) Pause processing (below). It applies to both servers.
   b) Server 1: steps 1 to 5.
   c) Server 2: steps 1 to 5.
   d) Server 1, then Server 2: step 6.
   e) Step 7, then Resume processing.
 Do not resume processing while only one server has the new files.

 GUI - pause processing
   1. Open the console in the browser and sign in (Admin or Developer).
   2. System > Pause processing.
   3. Dashboard: wait until no request is running.

 POWERSHELL

     (the menu window: '99', then 'XX').
   * Have ready: the console address, a Developer or Admin sign-in, and
     the date the service-account password was last changed
     (YYYY-MM-DD).
   * Free disk space on C: of at least twice the size of
     C:\FINESIII\app plus C:\FINESIII\data (for the zips and the

=====================================================================
 1  TAKE A BACKUP OF THE CURRENT FOLDERS (ZIPPED)
=====================================================================
 Back up by zipping the folders directly, and keep each zip in its own
 folder inside one backup folder. Nothing is changed yet; the bot may
 still run during this step.
   * The application folder is zipped now.
   * The data folder is zipped in step 4, AFTER the bot has stopped:
     while the bot runs, the audit database file
     (C:\FINESIII\data\finesiii_audit.db) and its spool are open, and a
     zip made then can fail ("used by another process") or hold an
     incomplete copy.

 GUI
   1. File Explorer: create the backup folder and its three parts:
        C:\FINESIII\backup-<stamp>
        C:\FINESIII\backup-<stamp>\app
        C:\FINESIII\backup-<stamp>\data
        C:\FINESIII\backup-<stamp>\settings
      Write the folder name down: steps 3, 4 and 8 need it.
   2. Zip the application folder:
      a) Open C:\FINESIII\app. Press Ctrl+A.
      b) Right-click one of the selected items > Send to > Compressed
         (zipped) folder. Wait until it has finished.
      c) Windows creates the zip INSIDE C:\FINESIII\app, named after
         the item you right-clicked. Rename it to app_<stamp>.zip, then
         Cut (Ctrl+X) and Paste (Ctrl+V) it into
         C:\FINESIII\backup-<stamp>\app. It must not stay in
         C:\FINESIII\app.
      (Simpler but slower: right-click the folder C:\FINESIII\app >
       Send to > Compressed (zipped) folder. That zip includes .venv;
       move it into the backup's app folder the same way.)
   3. Copy C:\FINESIII\app\.env into C:\FINESIII\backup-<stamp>\settings
      (copy, not move).
   4. Optional (Developer): console > Settings > Export configuration.
      Save the CSV into C:\FINESIII\backup-<stamp>\settings: a record of
      the settings as they are now (passwords are never in it).
   5. Check: double-click app_<stamp>.zip. It opens like a folder and
      shows config, desktop, src, unattended and the other folders and
      files of the application (no .venv). Close it.

 POWERSHELL

$stamp  = Get-Date -Format yyyyMMdd-HHmm
$backup = "C:\FINESIII\backup-$stamp"
'app', 'data', 'settings' | ForEach-Object { New-Item -ItemType Directory -Force -Path "$backup\$_" | Out-Null }
Set-Content -LiteralPath C:\FINESIII\last_backup.txt -Value $backup

# 1.1 Zip the application folder without .venv
Get-ChildItem -LiteralPath C:\FINESIII\app -Force | Where-Object { $_.Name -ne '.venv' } |
  Compress-Archive -DestinationPath "$backup\app\app_$stamp.zip" -CompressionLevel Optimal

# 1.2 The settings
Copy-Item -LiteralPath C:\FINESIII\app\.env "$backup\settings\.env"

# 1.3 Check the zip: number of files in the zip and in the folder
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z = [IO.Compression.ZipFile]::OpenRead("$backup\app\app_$stamp.zip"); "In the zip : $(@($z.Entries | Where-Object { $_.Name }).Count)"; $z.Dispose()
"In the folder: $((Get-ChildItem -LiteralPath C:\FINESIII\app -Recurse -File -Force | Where-Object { $_.FullName -notlike 'C:\FINESIII\app\.venv\*' }).Count)"
Get-ChildItem -LiteralPath $backup -Recurse -File | Select-Object FullName, Length
"Backup: $backup"
# [OK] the two numbers are equal; app_<stamp>.zip and .env are listed.
# [NG] Compress-Archive shows an error (for example a file in use or a
#      file over 2 GB): note the file named, and copy the folder
#      instead (without .venv) - stop here if that fails too:
#   robocopy C:\FINESIII\app "$backup\app\copy" /E /XD .venv /R:1 /W:1 /NFL /NDL /NP

 With either way: the database is not changed by this release, so no
 database snapshot is needed.

=====================================================================
 9  CRITICAL INFORMATION
=====================================================================
 9.1 CyberArk
   When the Fujitsu Mainframe password comes from CyberArk, CyberArk
   changes it. The bot never changes it then, neither automatically
   nor with "Change service-account password" (the console refuses),
   and the age line says "supplied and changed by CyberArk". The
   database-password copy from CyberArk is separate and not affected.

 9.2 Two servers - keep the automatic change OFF
   A password changed by the bot (automatically or from the console)
   is saved only in the Windows Credentials of the server that made the
   change. The other server keeps the old password: its sign-ins are
   refused, and after about 3 refusals the host locks the account.
   While both servers process Fujitsu Mainframe requests, keep
   "Service-account password: change automatically" OFF and change the
   password by hand as in 9.3. The bot then e-mails a reminder once a
   day from day 80, and an urgent e-mail every day from 5 days before
   the expiry.

 9.3 Changing the password by hand with two servers (GUI)
   1. System > Pause processing; wait until no request is running.
   2. Server 1 console: Settings > Fujitsu Mainframe terminal >
      Change service-account password. Wait for the result.
   3. Server 2: open ITS OWN console (http://127.0.0.1:8000 on that
      server) > Settings > Credentials and type the same new password
      for the Fujitsu Mainframe service account. Save (it applies at
      once). Then "Test sign-in and navigation" on server 2.
   4. Give the new password to the CyberArk / password-owner team as
      agreed (the e-mails never contain it).
   5. System > Resume processing.
   The bot allows one change per 24 hours, and only inside the Fujitsu
   Mainframe operating hours.

 9.4 Lock-out protection (automatic change, when switched on)
   At most one try a day. After 2 failed tries in a row it stops and
   sends an urgent e-mail. A refused current password stops it at once.
   An expired password (day 90 or later) is never changed by the bot:
   the host then only answers "password incorrect", and the password
   must be reset by the Fujitsu Mainframe team.

 9.5 Settings
   Leaving a number box empty and saving means "use the default"
   (90 / 80 / 5 / 2). Never type 0. Never save "change after" = 1 with
   "change automatically" On: the next hourly check would change the
   real password.

 9.6 Backups
   * Each backup is one folder C:\FINESIII\backup-<stamp> with a
     separate folder for each part (app, data, settings). Never put a
     backup zip inside C:\FINESIII\app or C:\FINESIII\data.
   * The zips and .env hold settings and audit data: keep them on the
     server (or a protected share), never in e-mail.

 9.7 Never during the update
   * Never stop the bot with Task Manager or "End" on the task.
   * Never zip the data folder while the bot runs.
   * Never copy the package over C:\FINESIII\app while the bot runs.
   * Never overwrite .env, the .venv folder or the data folder.
   * Never resume processing with only one server updated.
